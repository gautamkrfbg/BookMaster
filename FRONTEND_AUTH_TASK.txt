============================================================
1. CURRENT BOOKMASTER BUSINESS MODEL
============================================================

The intended final book lifecycle is:

ADMIN ADDS CATALOGUE BOOK
        ↓
BOOK APPEARS IN MARKETPLACE
        ↓
USER PURCHASES BOOK
        ↓
MOCK PURCHASE + BACKEND ACQUIRED COPY
        ↓
BOOK APPEARS IN USER'S LIBRARY
        ↓
USER CAN READ BOOK
        ↓
USER CAN LIST BOOK FOR EXCHANGE
        ↓
ANOTHER USER CAN REQUEST IT
        ↓
EXCHANGE COMPLETES
        ↓
RECIPIENT OWNS BOOK
        ↓
BOOK APPEARS IN RECIPIENT'S LIBRARY
        ↓
RECIPIENT CAN READ IT
        ↓
RECIPIENT CAN LIST IT FOR EXCHANGE AGAIN
   IF EXISTING EXCHANGE RULES ALLOW

There is NO separate concept of "purchased but not owned".

A purchased/acquired book is a legitimate user-owned book for exchange purposes.

The existing acquire implementation already creates a backend Book copy with:

- OwnerId = current user
- Status = OWNED
- IsCatalogue = false

Use this existing mechanism.

============================================================
5. IMPORTANT EXCHANGE DISTINCTION
============================================================

An exchange request involves TWO DIFFERENT BOOKS.

BOOK A:

The book the current user WANTS.

Example:

Moorland Whispers
        ↓
Listed by another user
        ↓
Current user wants this book

BOOK B:

The book the current user OFFERS in return.

Example:

FACE IN THE DARK
        ↓
Owned by current user
        ↓
Current user offers it

The requested book and offered book must not be confused.

Conceptually:

USER B WANTS:
    Book A

USER B OFFERS:
    Book B

Book B must be a legitimate currently-owned/available book belonging to User B.

============================================================
6. ELIGIBLE OFFER BOOK RULE
============================================================

A book should be available for selection as an exchange offer if:

- it belongs to the current user
- it is actually acquired/owned by the current user
- its backend status is OWNED
- it is not already LISTED
- it is not EXCHANGED/unavailable
- it is not the book being requested
- it is not another user's book

Books that MUST be eligible:

- books acquired through mock purchase
- books received through completed exchange

Books that MUST NOT be eligible:

- catalogue books not purchased
- books merely visible in Marketplace
- another user's books
- LISTED books
- EXCHANGED books
- the book currently being requested
- stale/nonexistent book IDs

IMPORTANT:

Do NOT determine eligibility solely from the visual badge:

"Purchased"

The Purchased badge is UI state.

The authoritative ownership information is the backend Book object.

The existing acquire endpoint creates an actual user-owned Book with:

OwnerId = current user
Status = OWNED
IsCatalogue = false

Therefore that book must be recognized as an eligible offer.
